# RS485 Subsystem — Build Plan

**Status:** Steps 1-3 (front end, protection network, connector) locked and
datasheet-verified. Schematic capture (KiCad) not started — next hands-on step.

## Scope

One isolated half-duplex RS485 bus (A/B differential pair) on IOBOARD, referenced to its
own isolated ground domain (`GND_RS485_ISO`, per the grounding architecture already fixed
for this project — isolated domains stay local to IOBOARD, never tied to `GND_LOGIC`). Not
in scope here: RS232 (separate subsystem, shares the same connector family convention but
different transceiver), PCB layout, exact connector pinout on the panel silkscreen.

## Design approach

Four decisions, in the order they were made:

1. **Transceiver: Mornsun TD321S485H-A (3.3V variant of the TD5(3)21S485H-A series),
   isolated RS485 module.** Already the standing choice for this project (see
   `hardware/datasheets/README.md`) — an isolated transceiver-in-a-module rather than a
   bare RS485 IC + separate isolator, consistent with the isolation approach already used
   for the analog subsystem. Full datasheet obtained and confirmed 2026-09-08: 3kVDC
   isolation, up to 500kbps, built-in 47kΩ pull-down bias on A/B, difference input
   impedance valid over -7V to +12V common-mode range, exact 10-pin pinout (below).
2. **Termination: 120Ω, switchable (jumper/DIP switch), not permanently populated.**
   Standard RS485 practice — only the two physical ends of a multi-drop bus should be
   terminated, and a gateway device doesn't know in advance whether it will sit at an end
   or in the middle of the run. Hard-wiring 120Ω would be wrong in the common case where
   this unit isn't the last device on the bus.
3. **External bias resistors: yes, included.** ~~Originally decided against these,
   reasoning the internal 47kΩ pull-down was redundant with them.~~ **Correction
   (2026-09-08):** Mornsun's own datasheet ships a second reference circuit, "Fig. 2: Port
   protection circuit for harsh environments," which explicitly adds external Rpullup
   (from VO/pin7) and Rpulldown (from RGND/pin10) on top of the internal bias — and that
   figure is Mornsun's answer to exactly our situation (industrial, not benign). Dropping
   external bias was inconsistent with also choosing the full harsh-environment protection
   tier in decision 4. See Step 2.
4. **Protection tier: full network (GDT + series R + TVS + common-mode choke), not
   TVS-only.** This is a general-purpose industrial gateway product, not a single
   fixed-site install with a known-benign cable run — the actual field environment
   (proximity to VFDs/motors/contactors, indoor/outdoor, cable length) is unknown at
   manufacturing time and out of this project's control. Basic TVS-only is the right
   choice only when the installation is known to be short, indoors, and away from
   switching inductive loads; that can't be assumed here. As of 2026-09-08 this network is
   no longer a generic industry-practice cascade — it's Mornsun's own published
   harsh-environment reference circuit for this exact transceiver. See Step 2.

## Step 2 results: protection network (2026-09-08, corrected same day)

### Reasoning: why the full network, not TVS-only

A basic TVS clamps fast transients but has limited energy-handling capacity and can't
survive a sustained or high-energy surge (induced lightning coupling, a nearby motor/VFD
switching event coupling into a long cable run). A gas discharge tube (GDT) handles the
high-energy front end (survives kA-level 8/20µs pulses) but is too slow and has too high a
follow-on voltage to protect the transceiver by itself. The standard pattern is a cascade:
GDT absorbs the bulk of the energy, series resistors limit current into the fast clamp
during the GDT's turn-on delay, TVS diodes do the fast low-voltage clamp right at the
transceiver, and a common-mode choke suppresses the EMI/common-mode noise a GDT+TVS
network doesn't address at all.

### Correction: this is now Mornsun's own reference circuit, not a generic cascade

The first pass at this step (component table below, superseded) was built from a generic
Bourns RS-485 port-protection evaluation-board note, because the transceiver's own
datasheet couldn't be read for a pin diagram (see the schematic-capture blocker below).
Once the full Mornsun datasheet was obtained, it turned out to contain its own "Fig. 2:
Port protection circuit for harsh environments" — literally labeled for our exact
situation — with named parts and values. That supersedes the generic cascade: a
manufacturer's own tested reference circuit for this specific transceiver beats a good
generic industry pattern.

**Superseded (2026-09-08, same day — kept for traceability):** Bourns CDSOT23-SM712 (TVS)

Signal-integrity check against the 500kbps max data rate (Step 1): none of the newly
selected parts are datasheet-specified with a capacitance/inductance figure precise enough
to redo the earlier margin math, but a signal-line-rated common-mode choke (TDK's own
ACM2520 series, sized for this class of interface) and small-package TVS diodes are, if
anything, a better signal-integrity fit than the higher-capacitance generic parts they
replaced. No new concern raised.

### Still open (flag, not blocking)

- **Rpullup/Rpulldown exact resistor value.** Mornsun gives a current ceiling (<25mA) but
  not a recommended resistance. A typical RS485 bias value (commonly 560Ω-4.7kΩ) would sit
  safely under that ceiling; needs a specific pick before schematic lock, not urgent since
  it's a placeholder-friendly passive.
- **Bias polarity double-check.** Reading Fig. 2's layout, Rpullup (from VO, +5V isolated)
  lands on the **B**-side node and Rpulldown (from RGND) lands on the **A**-side node. That
  is Mornsun's own tested circuit, so it should be correct for how this module defines A/B
  internally — but it's worth a careful visual re-check against the datasheet figure itself
  when wiring in KiCad, since a swapped pull-up/pull-down would flip the bus's idle state.
- **B3D090L vs B3D090L-C.** Mornsun names the base part "B3D090L"; Bencent's orderable SMD
  part is "B3D090L-C". Treating these as the same device (the suffix denoting Bencent's own
  case/lead variant) — reasonable but not independently confirmed against a Bencent
  part-numbering guide.

## Step 3 results: connector (2026-09-08)

**Phoenix Contact MC 1,5/3-ST-3,5** (MPN 1840379) — same family already used for J1
(power input, 1840366), J2 (digital inputs), J3 (relay outputs), and J4 (analog I/O,
1840382): 3.5mm pitch, 28-16AWG (1.5mm²) screw terminals, through-hole pluggable, 3
positions. Confirmed in stock via Newark/Farnell/RS listings.

3 positions, not more: A, B, and one **GND_RS485_ISO** reference pin — matches the
isolated-domain pattern already used for the analog connector (one shared isolated
return, not a per-signal return), and matches what the transceiver module actually needs
(the isolated side only ever sees A, B, and its own isolated ground). Rated 8A/160V, which
is heavy overkill for signal-level current — kept anyway for BOM/part-family consistency
with J1-J4, same reasoning already used project-wide for reusing one connector family
across subsystems.
